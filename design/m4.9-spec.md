# M4.9 — Implementation Spec (Real Typechecker + Mid-Level IR)

**Status:** working draft — the ordered work plan for M4.9, the semantic-analysis layer inserted before M5. Decisions here were made 2026-07-21; the design home for compiler architecture is `compiler.md` (this realizes §1 mid-level IR and part of the tooling posture in §3).

**Why it exists:** discovered while grounding M5 Phase A against the code. The current `Typechecker.swift` does no expression typing — only type-kind collection, the POD rule, and let/var. Actual type resolution lives ad-hoc in codegen (`typeOf` + `Scope: [String: String]`). And there are no instance methods on `struct`/`enum`/`class`. M5's interfaces and generics need real type information this can't provide, so M4.9 stands up the semantic layer first.

---

## 1. Scope

**Ships in M4.9:**
- A real internal **`Type` model**, replacing string-typing (`TypeRef.name`, `Scope: [String: String]`).
- A **semantic-analysis pass**: name/scope resolution, expression typing, call/argument checking (arity, labels, types), field + method member resolution, return-type checking. It **produces the typed IR directly** (§4) — there is no separate typed-AST data structure (see §2).
- **Instance methods on `struct`/`enum`/`class`** (reusing `fun`; no new keyword). Read-only in M4.9.
- A **structured, typed mid-level IR** (see §4), produced by the checker; **codegen rewritten to consume it** instead of re-deriving types with `typeOf`.
- **Exhaustiveness** as an IR pass (moved out of codegen / made real).
- **Collected diagnostics** (collect-and-continue), replacing exit-on-first-error.
- **A typed dump** — a `--dump-typed-ast` mode alongside the existing `ASTDump`/`EmitMode` path, printing the **typed IR** (the AST's information, now resolved + typed). The minimum debug visibility into the typecheck phase; also a golden-test oracle for the checker. (IR-after-passes dump + full per-phase golden testing stay deferred — `compiler.md` §8.)

**Deferred:**
- **Query-based / demand-driven compiler server** (`compiler.md` §3) — conventional passes for now; query engine later (tooling milestone).
- **CFG / SSA IR** — the IR stays structured (§4); a lower CFG/SSA level lands in M6 when escape analysis / GC barriers need it (Rust THIR→MIR pattern).
- **Closure conversion as a formal IR pass** — closures stay first-class in the IR; codegen keeps lowering them as today. Promoting it to an IR pass (`compiler.md` §1) comes later.
- **Mutating methods on value types** — arrive with property setters (M5-A4).
- **Overloading** — names stay unique in M4.9 (overload resolution is M5, `interfaces.md` §4.2).
- Interfaces, generics, `any`/`some`, `shared` bound — all M5.

## 2. Pipeline

```
source
  → Lexer → tokens
  → Parser → AST            (unchanged shape; + method members)
  → Typecheck → typed IR    (resolve names/members/methods, type exprs, build the structured typed IR; diagnostics)
  → IR passes               (exhaustiveness now; hooks for closure-conv, monomorphization, escape/barriers later)
  → Codegen (emit C)        (walks the IR; no more typeOf)
```

**Two representations, Rust-staged.** The untyped **AST** (parser output, `AST.swift`) and one **typed structured IR** the checker produces from it. There is deliberately no separate "typed AST" structure: our AST is immutable `enum`s — unlike Swift's mutable AST, which Sema annotates *in place* — so typing means producing new nodes rather than decorating existing ones, and since we want an IR for passes/codegen anyway, the checker builds that typed IR directly.

Lineage (why these two and not more):
- **Swift:** one AST, type-checked *in place* (mutable nodes gain a `Type`), then SIL (a separate CFG IR). In-place works because Swift's AST is mutable classes — which ours is not.
- **Rust:** a new structure at each altitude — AST → HIR (desugared, untyped-in-tree; types in side-tables keyed by node id) → **THIR** (typed tree) → **MIR** (CFG). Never annotates in place.
- **Us:** our typed structured IR ≈ **Rust's THIR**; the CFG/SSA level deferred to M6 ≈ **Rust's MIR / Swift's SIL**. We skip a separate untyped-desugared level (Rust's HIR) — AST goes straight to the typed IR — because M4.9's desugaring is minimal. Corroboration: Rust runs exhaustiveness on THIR (the typed tree), exactly where we put it (§5 T4).

## 3. The Type model

Replace `String` types with an internal `Type` (extensible toward generics):

- `.int`, `.bool`, `.string`, `.void`
- `.named(name, kind)` — kind ∈ {struct, enum, class, actor}
- `.function(params: [Type], ret: Type)`
- (later, M5) `.typeParam`, `.existential(interface)`, `.opaque`, `.generic(base, args)`

Symbol tables built during resolution: type declarations and their **members** (fields, cases, methods), function signatures, and a lexical **scope stack** for locals/params. `TypeRef` (syntax) resolves to a `Type` (semantics) once, in the checker.

## 4. The mid-level IR (structured, typed)

**Altitude — structured, not CFG/SSA.** Keeps `if`/`switch`/loops as nested nodes and closures first-class, so codegen stays mechanical and the C backend keeps structured control flow. Every node is **typed** and carries a **source span** (debug info threaded from the start, `compiler.md` §1). The checker builds it **directly** from the untyped AST — there is no intermediate typed-AST structure. This is the M4.9 analog of Rust's THIR (§2).

Sketch:
- `IRModule { decls }`
- Decls: typed struct/enum/class/actor (fields, cases, **methods**), typed function.
- Stmts: `Let`, `Assign`, `Return`, `If { cond, then[], else[] }`, `Switch { subject, arms[] }`, `ExprStmt`, `SpawnLet`.
- Exprs (each carries its `Type` + span): `IntLit`, `BoolLit`, `StringLit`, `VarRef(symbol)`, `FieldAccess(base, field)`, `MethodCall(receiver, method, args)`, `Call(callee, args)`, `Binary(op, l, r)`, `Closure(...)`.

Member/method dispatch is **resolved in the IR** (a `MethodCall` names its concrete target), so codegen never re-resolves. This is the seam M5 extends: `MethodCall` gains a dynamic/witness form for `any`, and generic calls carry witness arguments.

## 5. Phased plan

Thin vertical slices; each keeps the existing examples compiling.

### T1 — Type model + semantic pass (produces the typed IR) + diagnostics
First, **span plumbing** (separable as a tiny T0): add column/offset tracking to the lexer and carry a rich `Span` (§6) on tokens and AST nodes, replacing `line: Int`, so diagnostics and IR nodes get precise `begin..end` ranges. Then introduce `Type`; resolve names/scopes/members; type every expression; check calls (arity/labels/types), field access, returns; build the structured typed IR (§4). Collect diagnostics (collect-and-continue). Codegen unchanged this slice (still the AST/`typeOf` path), so nothing regresses while the checker + IR come up alongside; `--dump-typed-ast` is the consumer that validates them.
- **Exit:** every existing example typechecks and lowers to the typed IR; `--dump-typed-ast` prints it; representative type errors report as collected diagnostics rather than `exit(1)` on the first.

### T2 — Codegen consumes the typed IR  *(the bulk / main risk)*
Rewrite `Codegen.swift` to walk the typed IR and delete `typeOf`/string-typing. Existing feature set only — no new language features — so output should be equivalent and diffable. Runtime preamble untouched; only per-node emission changes.
- **Exit:** all existing examples produce equivalent C via the IR path; `typeOf` gone from codegen; output diffs reviewed.

### T3 — Instance methods on types
Parse `fun` in struct/enum/class bodies; bind `self` (immutable); resolve `receiver.method(...)` in the checker; represent as an IR `MethodCall`; codegen emits `Type_method(self, …)` (mirroring actor handlers). Now end-to-end on the unified IR path.
- **Exit:** a struct/class with a method compiles and runs; `s.method()` resolves and types; a missing method is a clean diagnostic.

### T4 — Exhaustiveness as an IR pass
Implement `switch` exhaustiveness as a pass over the typed IR (confirm current enforcement first — it may be unchecked today).
- **Exit:** a non-exhaustive `switch` is a collected diagnostic; exhaustive ones compile.

**Dependencies:** T1 → T2 → T3; T2 → T4. Codegen moves to the IR path on the existing feature set first (T2, diffable), then methods are added on the unified path (T3).

## 6. Cross-cutting decisions

- **Inference stays modest** — bottom-up expression typing plus declared annotations; `let x = expr` infers from `expr`; return checked against the annotation; closure params from their annotations. No HM/global inference (generic inference is M5).
- **Diagnostics** — a `Diagnostic { message, span, severity }` collected in a context and reported together; typechecker-level recovery now, parser error-recovery (`compiler.md` §3) later.
- **Debug info / spans** — a rich `Span { file, begin: (line, col), end: (line, col) }`, threaded from the **lexer** (which gains column + offset tracking) through tokens and the AST into the IR; every node carries one and every future pass preserves it (`compiler.md` §1, §3–§4). Replaces the current `line: Int` on tokens and AST nodes. Diagnostics render precise `begin..end` ranges. Decided rich-now because retrofitting positions is miserable and diagnostics/LSP/DWARF all need them.
- **The IR is the M5 seam** — `MethodCall` and the conformance/symbol tables are shaped so M5 adds witness dispatch, `any`/`some`, and generic witness-passing as extensions, not rewrites.

---

## 7. Risks / watch items

- **Codegen rewrite (T2)** is the largest chunk and the regression risk; guard it by diffing emitted C for every example before/after, on the unchanged feature set.
- **Typing and IR-building run together** — the checker both types and builds the IR in one pass. Keep the pure semantic checks legible/separable in the code even though they run alongside IR construction, so the typechecking logic stays reusable.
- **Exhaustiveness today** — verify where/whether it's currently enforced before T4 so we don't silently change behavior.
- **Scope creep toward the query engine** — hold the line: conventional passes now, demand-driven later.
- **Codegen special-cases the T2 rewrite must absorb** (they live in today's AST walk and can't just vanish):
  - **Builtins** — `print`, `readLine`, `concat`, `sleep` are matched by name in `emitCall`. Model them in the symbol table (with signatures) so the checker types them and the IR carries them as calls/intrinsics.
  - **Actor-handler dispatch** — `c.handler(...)` → `Actor_handler(c, ...)` is pattern-matched in codegen. Move resolution into the typechecker; the IR `MethodCall` (or an actor-send form) names the target.
  - **Share analysis** — the shareability diagnostics (spawn-capture check, actor-handler param check) currently live in codegen. Keep them there for M4.9; they become an IR pass with M5's shareability work (`compiler.md` §1, `concurrency.md` §5). Just don't lose them in the rewrite.
  - **Closure conversion** — stays in codegen for M4.9 (closures remain first-class in the IR); promoting it to an IR pass is later.
- **Span refactor churn** — replacing `line: Int` with `Span` touches every token/AST construction site and the existing `error:line:` print sites (lexer, parser, typechecker, codegen diagnostics). Mechanical but broad; do it first (start of T1) so everything else builds on it.
- **The checker/IR runs alongside codegen's `typeOf` during T1** — T2 switches codegen over. Validate the checker via `--dump-typed-ast` against existing behavior before flipping, so the cutover doesn't change output silently.
