# M4.13 — Implementation Spec (C-source split + Nomu prelude)

**Status: DONE (2026-07-24).** All exit criteria green; `bazel test //...` passes and every example runs with identical output. Implementation notes at the end. Below is the plan as built. It was an M5-adjacent slice.

**Superseded in part by M4.14 (roadmap):** the runtime files were renamed `runtime.c`/`core.c`/`runtime.h` (reflected below), and compiler outputs now persist under `<project-root>/build/` instead of the temp dir this spec describes (§3, §8). The embed-and-emit packaging and relocatable-binary property are unchanged. Two coupled pieces: (1) move the emitted C runtime out of an embedded Swift string into real `.c`/`.h` files organized by trust level, and (2) add a **prelude-compilation mechanism** so a Nomu-written standard library compiles alongside user code. Adds **no** new syntax or keywords — it is a build/codegen refactor plus a driver mechanism.

**Why now.** The runtime is currently one big Swift string literal (`NomuRuntime.preamble` + `cMain` in `compiler/codegen/sources/Runtime.swift`), spliced verbatim into a single generated `.c` file. That is fine at M4 scale and painful past it: editing the scheduler means editing escaped string literals, there is no header/ABI boundary, and there is nowhere for a real standard library to live. M5 adds new runtime object shapes (witness tables, `any` boxes) and its first generic types (`Option`/`Result`/`Box`) — both want an organized home. Doing the split now means those land in real files from the start rather than being retrofitted. It hard-gates M5 Phase B (which needs a prelude home for `Result`/`Option`); doing it before Phase A is the recommended sequencing so Phase A's new runtime pieces are organized too.

**Decided direction (from the design discussion, 2026-07-24):**
- The **standard library is written in Nomu** and recompiled with each build (dogfooding chosen over compile caching; it also front-loads LLVM test surface at M8).
- **`String` stays a C primitive for now** (like `Int`). Implementing it in Nomu needs a runtime-sized **indexable buffer primitive** the language lacks; that primitive is the same one collections need and is designed deliberately post-M5. So the C floor keeps `String` and the primitive value/IO builtins; the Nomu prelude starts with what needs no new primitives.

**Repository layout.** All non-tooling code lives under a **single** repo-root directory (build tooling stays in `tools/`). That directory is `compiler/` today; since it will now hold the runtime and stdlib alongside the compiler, M4.13 **renames it `src/`** and nests the new pieces under it: `src/runtime/` (the C floor) and `src/stdlib/` (the Nomu prelude), beside the existing `src/frontend`, `src/driver`, `src/codegen`, `src/nomu-cli`. The rename touches the Bazel package paths, the `//:install` target, and the `bin/nomuc` label — mechanical, done once now before more milestones accrete paths. (`examples/`, `design/`, `bin/` stay put.)

## 1. The three levels as files

Three conceptual levels — **privileged runtime**, **standard library**, **user code** (the model from the design discussion). The standard-library level is currently split *by implementation language*: a Nomu part and a C floor, because `String` and the primitive value/IO operations can't be Nomu until the buffer primitive exists. So **three levels, four files** — the stdlib level spans two of them and the C floor shrinks as primitives migrate up.

| Level | What | File(s) | Language |
|---|---|---|---|
| **1 — Privileged runtime** | scheduler, allocator, poller, timer, `main` bootstrap, and the blocking primitives (`readLine`, `sleep`) whose implementations manipulate fiber state | `src/runtime/runtime.c` (+ `runtime.h` ABI header) | C |
| **2 — Standard library** | the library user code calls. **Nomu part:** `Option`/`Result`/`Box`, seeded at M5 Phase B/E. **C floor:** `String` + pure value ops (`concat`, `print`), the `Closure`/`ObjectHeader` types — the not-yet-Nomu remainder, which shrinks as primitives migrate up | `src/stdlib/*.nomu` **+** `src/runtime/core.c` | Nomu + C |
| **3 — User code** | the program | generated `user.c` | Nomu → C |

**Placement principle** for where a builtin's *implementation* lives: a **pure value op** (`concat`, string literals, `print`) goes in the stdlib C floor (`core.c`, depends only on `rt_alloc`); a **fiber-touching op** (`readLine`, `sleep`) goes in the privileged runtime (it suspends fibers via `swapcontext` on scheduler-internal thread-locals). The user-facing *surface* of both is a stdlib builtin the compiler lowers to an `rt_*` call — the trust boundary, not the surface, decides which file holds the implementation. Both C files include `runtime.h`.

**Shared ABI header — `runtime.h`.** The shared types (`ObjectHeader`, `String`, `Closure`, `SpawnHandle`) and the prototypes for every symbol the generated code or the other C files call (`rt_alloc`, `rt_str_concat`, `rt_read_line`, `rt_sleep_ms`, the scheduler entry). Splitting into separate translation units forces the shared symbols from `static` to external linkage with prototypes here — the header/ABI boundary the LLVM move (M8, `compiler.md` §6) needs anyway, and the "explicit, scannable object model / single allocation seam" hygiene m5-spec §5a asks for.

## 2. Prelude compilation

The driver compiles the Nomu standard library **together with** user code:

- Read the `src/stdlib/*.nomu` sources, parse them, and **prepend their decls** to the user `Program` before the extension-merge / typecheck / Sema / codegen pipeline. Under the single compilation unit this is exactly a decl concatenation — no import system, no separate module.
- Prelude symbols are then ordinary top-level declarations, visible to user code with no `import`. The prelude cannot reference user code (it is prepended); user code can call the prelude freely.
- **Recompiled every build** — accepted per the dogfooding decision. This is no worse than today, where the whole preamble is part of the single compiled `.c`; it is the same work reorganized into translation units. A `.o`/`.a` cache is a later performance option, not M4.13.
- **Diagnostics** carry their source file already (`Span.file`), so a prelude error points at the prelude source. Prelude names are effectively **reserved** under the single CU — a user redeclaring a prelude name is a duplicate-declaration error; real namespacing waits on the module system (`modules.md`).

M4.13 seeds `src/stdlib/` with a few **genuinely useful monomorphic `Int` helpers** — `abs`, `max`, `min` — rather than a throwaway placeholder; they need no generics or new primitives and dogfood the real path. (When generics land, a generic `max<T: Comparable>` etc. supersedes them — a rename/replace to reconcile at that point.) The first generic citizens — `Option`/`Result`/`Box` — arrive at **M5 Phase B/E**.

## 3. Packaging — embed-and-emit

`nomuc` stops being self-contained the moment the runtime leaves the binary, so it must find the C floor and the prelude at compile time. Chosen approach: **the real `.c`/`.h`/`.nomu` files are the editable source of truth, and a build rule embeds their contents into the `nomuc` binary as string resources** (the same shape as today's `Runtime.swift`, but generated from real files instead of hand-maintained as escaped literals).

At compile time `nomuc`:
1. writes `runtime.c`, `core.c`, `runtime.h` to a temp dir,
2. parses the embedded prelude source alongside the user program (§2),
3. emits `user.c` (which `#include`s `runtime.h`),
4. invokes `cc` over `user.c runtime.c core.c`.

This keeps `nomuc` a **single relocatable binary** (copying `bin/nomuc` elsewhere still works, matching today's hermetic behavior) while making the sources real files. Alternatives considered and deferred: referencing installed sources next to `bin/nomuc` (makes `nomuc` non-relocatable) and linking a prebuilt `libnomu_rt.a` (faster builds, platform-bound `.a`, install-time compile) — the archive is a sensible later optimization once compile time matters.

## 4. Compiler surface touched

- **`compiler/` → `src/` rename** — the single code dir gains the runtime and stdlib, so it is renamed; update the Bazel packages (`//compiler/...` → `//src/...`), the `//:install` and `nomuc` aliases, and `bin/`’s copied-artifact label.
- **`src/runtime/` (new)** — `runtime.h`, `runtime.c`, `core.c`, carved out of the current `NomuRuntime.preamble`/`cMain` string. De-`static` the shared symbols; add their prototypes to the header.
- **`src/stdlib/` (new)** — the Nomu prelude sources (seeded with `abs`/`max`/`min` on `Int`).
- **Build** — a rule embeds `src/runtime/*` and `src/stdlib/*` into the codegen/driver target as string resources; `Runtime.swift` shrinks to (or is replaced by) the generated embedding.
- **`CodegenIR.emit()`** — stop splicing the preamble/`cMain` into the body; emit only `user.c` with the `#include`. The `main`→`nomu_main` rename stays; `int main()` moves into `runtime.c` with `extern void nomu_main(void);`.
- **`Driver.swift`** — prepend the parsed prelude decls to the program; write the temp C files; pass all C sources to `cc`.
- **Builtin lowering** — unchanged in shape: `print`/`concat`/`readLine`/`sleep` still lower to the same `rt_*` calls, now resolved across translation units via the header instead of an in-file `static` definition.

---

## 5. Exit criteria

1. Every existing example and test compiles and runs **identically** — the split is behavior-preserving (`bazel test //...` green; the `examples/` set produces the same output).
2. The runtime/core C lives in real `.c`/`.h` files, compiled as **separate translation units**; shared symbols are declared in `runtime.h` and are no longer `static`.
3. `nomuc` remains a **single relocatable binary** — copying `bin/nomuc` to another location and compiling a program still works.
4. A declaration in `src/stdlib/*.nomu` is callable from a user program with **no import**; a program that calls a seeded helper (`abs`/`max`/`min`) compiles and runs.
5. `String` and the value/IO builtins (`concat`, `readLine`, `sleep`, `print`) behave exactly as before.

---

## 6. Non-goals / deferred

- **`String`/collections in Nomu** — needs the runtime-sized **indexable buffer primitive** (safe builtin `Array`/`Buffer` vs. unsafe raw-pointer intrinsic is the real fork); designed deliberately post-M5, alongside collections. Until then the C floor keeps `String`.
- **`.o`/`.a` precompilation of the C floor** — a build-time optimization for later; M4.13 recompiles it each build.
- **Module system / prelude namespacing** — later (`modules.md`); prelude names are reserved under the single CU for now.
- **Loops** — a Nomu stdlib can lean on recursion until loops land; not part of this slice.

---

## 7. Relationship to M5

M4.13 builds the **mechanism**; M5 Phase B/E provide the **first generic citizens** (`Option`/`Result`/`Box` as `src/stdlib/*.nomu`), which closes the "no home for `Result`/`Option`" gap noted in the M5 audit. It also hands M8 (LLVM) immediate Nomu-stdlib test surface. Sequencing: M4.13 hard-gates Phase B; recommended before Phase A so Phase A's new runtime shapes (witness tables, `any` boxes) are authored in the organized C floor from the start.

## 8. Implementation notes (as built)

- **Rename.** `git mv compiler src`; every `//compiler/...` Bazel label → `//src/...` (root alias, `//:install`, package deps).
- **C files** — `src/runtime/{runtime.h, runtime.c, core.c}`, carved from the former `NomuRuntime` string. Scheduler/timer/poller internals stay `static`; the symbols generated code calls (`rt_alloc`, `rt_free`, `rt_str_lit`/`rt_str_concat`, `rt_sleep_ms`, `rt_read_line`, `fiber_spawn`, `spawn_join`) have external linkage via the header. `int main` + the entry live in `runtime.c`.
- **ABI header include set.** Generated `user.c` includes only `runtime.h`, which pulls `stdint`/`stddef`/`stdio` (types + `printf`) and `pthread` (generated actor code declares `pthread_mutex_t` and locks inline). Grounding every example surfaced two symbols the generated code takes from libc — `pthread_*` (actors) and `free` (actor deinit). `free` was routed through a new **`rt_free` dealloc seam** (pairing `rt_alloc`) so `<stdlib.h>` stays *out* of `user.c` — which also avoided a name clash between the prelude's `abs` and libc's `abs`, and shrinks the libc-collision surface generally (see the deferred mangling cleanup, `m5-spec.md` §7).
- **Embedding** — `src/runtime/embed.sh` + a genrule generate `EmbeddedSources.swift` (raw Swift strings, so the `.c`/`.h`/`.nomu` pass through verbatim); `swift_library //src/runtime:embedded` is a driver dep. `nomuc` stays a single relocatable binary.
- **Prelude** — `src/stdlib/core.nomu` (`abs`/`max`/`min`). `Driver` lexes+parses it and prepends the decls (needs a new `public init` on `Program`), after the `--emit-ast` dump (so that view stays user-only) and before extension-merge.
- **Codegen** — `emit()` drops the preamble/`cMain` splice and prepends `#include "runtime.h"`; `Runtime.swift` deleted. Binary mode writes `user.c` + the three runtime files to a temp dir and `cc`s them with `-I`; `--emit-c` writes the self-contained set beside the source.
- **Tests** — the codegen unit tests that asserted on now-relocated preamble text were updated (they assert the header include and user-level output instead). Example: `examples/stdlib.nomu`.
