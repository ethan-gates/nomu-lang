# M8 · 8.4 — GC substrate: statepoints, stack maps, inlinable seams

**Status:** 8.4.0 (spike), 8.4.1 (address-space migration + pass pipeline), and 8.4.2 (loop-
back-edge safepoint polls) implemented and green (2026-08-03); 8.4.3–8.4.4 pending. Two D1
mechanisms changed under what the LLVM pass actually accepts — see **"Implementation note
(8.4.1)"** below and the revised D1 bullets. The D3 poll form is deferred to M6. Expands
`m8-spec.md` §8.4. Co-designed with
`m6-spec.md` §6.1 (object model) — every decision here is governed by *what a moving, precise
collector needs*, chosen for **runtime performance first, yielding only to soundness**.

**Prerequisite:** loops (`loops.md`). 8.4.2 places a safepoint on each loop back-edge, so the
loop construct must exist and lower first. Everything else in 8.4 is loop-independent; see the
sequencing note in `loops.md`.

Deps: 8.2 (full lowering), 8.3 (debug info, done), loops. Serves M6 (precise roots + moving GC)
and M7 (cancellation polls) / runtime preemption — the safepoints here are **triple-purpose**
(`m8-spec.md` §8.0.5).

---

## What 8.4 delivers, and what it does not

8.4 builds the **machinery**, inert. After 8.4 the compiler emits statepoint-based safepoints,
parseable stack maps, and inline-shaped alloc/barrier/poll seams — but no object moves, no
barrier fires, no poll is ever armed. The observable behavior of every program is **unchanged
vs. 8.2** (the corpus still produces byte-identical output). M6 fills the seams and turns on
collection; M7 arms the poll. The bet (`m8-spec.md` §8.0.7): the mutator-performance
battleground is these seams, so their *shape* — inline fast path, call only on the slow path —
must be right now, because M6 cannot retrofit inlinability into a call stub.

## Decisions

### D1 · Pointer / address-space model — `addrspace(1)` = managed reference

`RewriteStatepointsForGC` finds roots by tracking `addrspace(1)` (GC) pointers; it demands that
**every GC pointer live across a safepoint be discoverable and relocatable**. The model, chosen
to minimize both rewrite-pass work and cross-safepoint reload overhead (8.0.7):

- **`addrspace(1)` means "pointer to a GC-allocated object."** Applied to: class object
  pointers, actor object pointers, the closure object, the `any`-box object, `spawn` result boxes —
  and (M6) the `String` character buffer if String becomes GC-managed. These are the values that
  keep heap objects alive and may be live across a call. (Closures and `any I` values are
  themselves a single `addrspace(1)` pointer to a heap box — see the *Implementation note* below.)
- **`addrspace(0)` stays for everything that never points into the GC heap:** format-string
  globals, the actor mutex `void*` from `rt_mutex_new`, witness-table globals (static, never
  moved), C-ABI scratch — **and, in 8.4, the `String` character buffer**, which is runtime-owned
  (`rt_str_*`, non-moving) today. Whether `String` becomes a GC object is an M6 object-model call;
  8.4 leaves it `addrspace(0)` to stay minimal. Not tracked, not relocated — zero cost.
- **Interior/field pointers stay `addrspace(1)`.** A GEP into a GC object is a *derived* pointer;
  the rewrite pass relocates it with its base. Keeping field addresses in `addrspace(1)` is what
  lets a live `&obj.field` survive relocation.
- **Classify per field inside the heap-box layouts.** The closure box is `{fn, caps…}` — the `fn`
  code pointer is `addrspace(0)`, each captured reference field is `addrspace(1)`. The `any`-box is
  `{witness, payload}` — the `witness` (a static table) is `addrspace(0)`, `payload` is
  `addrspace(1)`. A `spawn` handle's fiber pointer is `addrspace(0)` (runtime-owned), while its
  boxed **result** is `addrspace(1)`. A reference-typed enum-payload field loads as `addrspace(1)`.
  (These fields live *inside* a heap box now, not inside a by-value SSA aggregate — see the
  *Implementation note*.)
- **The C-ABI boundary casts explicitly, in the `1 → 0` direction only.** Runtime C functions speak
  `addrspace(0)` (C has no address spaces). At a runtime call taking a managed object we
  `addrspacecast (1 → 0)` for the call; the `addrspace(1)` value the mutator holds is the tracked
  root, the `addrspace(0)` copy handed to C lives only for the call. The **allocator itself is
  declared to return `addrspace(1)`** (`rt_alloc : (i64) -> ptr addrspace(1)`), so managed memory
  enters address space 1 *at the allocation*, not via a `0 → 1` cast at the use site — the pass
  rejects the latter (see *Implementation note*). The C ABI is unaffected: `addrspace(1)` is a plain
  64-bit pointer on arm64.

**Soundness note carried to M6 (not resolved here, because nothing moves yet):** a runtime C
function that both (a) can trigger GC and (b) holds an object pointer risks a stale
`addrspace(0)` copy if the object moves. The object is *kept alive* (the mutator's `addrspace(1)`
root is on the stack map), but a moving collector could relocate it under C's feet. M6 resolves
this with **pinning or non-moving runtime interfaces** for those calls (`m6-spec.md` §6.1); 8.4
keeps the boundary explicit (one cast site per crossing) so M6 can slot pinning in without
re-plumbing. For the inert phase the runtime never moves, so this is latent.

**Performance rationale:** narrowing `addrspace(1)` to genuine managed references (not "all
pointers") keeps the rewrite pass's live-set small, which directly shrinks the spill/reload
overhead statepoints add around each safepoint — the primary cost of this root mechanism (8.0.8).

**Scope — the *full* managed set, in 8.4 (Decided 2026-08-03).** 8.4 migrates every `rt_alloc`-d
reference — class/actor object pointers, closure `env`, `any`-box payload, `spawn` box — **and
their interior/field GEPs** — to `addrspace(1)` now, not just the most-visible class/actor
pointers. The reason is **risk isolation, not performance** (nothing moves in 8.4, so address
space is behavior-neutral): env/box/spawn are as GC-managed as class objects, so leaving them
`addrspace(0)` is not a smaller-but-correct model — it is *unsound* under M6 (an untracked root →
use-after-free once the collector reclaims/moves). Doing the whole migration while the phase is
**inert** is exactly when it's cheap to verify — the LLVM verifier rejects every address-space
mismatch on the spot, the corpus stays byte-identical, and the 8.4.3 smoke test confirms the roots
recover — with no live collector to confuse the diagnosis. Splitting it would hand M6 an invasive,
correctness-critical migration layered on top of collector bring-up, where an addrspace bug and a
collector bug look alike. The `rt_alloc` set is stable (M6 reroutes it, doesn't restructure it), so
there's little churn to lose. Gated behind the 8.4.0 spike (don't migrate all of `Lowering.swift`
until the pass is proven to link + emit stack maps through our C API).

**Implementation note (8.4.1) — two mechanisms this LLVM's `RewriteStatepointsForGC` forced.**
The migration landed byte-identical, but two D1 details as first drafted are not what the pass
accepts on our LLVM. Both are settled and reflected in the D1 bullets above.

1. **Managed memory enters `addrspace(1)` at the allocator, not via a `0 → 1` cast.** The draft
   plan (`rt_alloc` returns `void*`, `addrspacecast (0 → 1)` at each alloc site) makes the pass
   assert: `findBaseDefiningValue` strips pointer casts and requires the base's address space to
   match, so a `0 → 1` cast is not a legal way to introduce a GC base. Fix: declare
   `rt_alloc : (i64) -> ptr addrspace(1)`. The call *is* the base; no cast. Only `1 → 0` casts
   remain (at the `fiber_spawn` env arg, the spawn routine's return to the runtime, and the
   struct-mutating witness-thunk `self`), and those are supported (they leave GC-space). M6's inline
   TLAB fast path (D5) likewise yields `addrspace(1)` directly, so this matches the intended end
   state.

2. **`any I` and closures are heap-boxed reference values, not by-value aggregates.** The pass
   cannot relocate a GC pointer nested inside a **first-class aggregate** (struct/array SSA value)
   that is live across a safepoint (`computeLiveInValues`: *"support for FCA unimplemented"*). The
   8.2.5/8.2.6 representations — `any I` as a by-value `{witness, payload}` and a closure as a
   by-value `{fn, env}` — put an `addrspace(1)` pointer inside exactly such an aggregate whenever
   the box/closure crosses a call. Fix: both become **heap-boxed reference values** — the box lives
   in an `rt_alloc`'d object and the `any`/closure *value* is a single `addrspace(1)` pointer to it.
   Nothing then crosses a call as an FCA; the value is one scalar GC reference the pass tracks, and
   the payload/env are `addrspace(1)` fields of a heap object (heap-to-heap references traced by the
   object map in M6 — D6's "never stack roots"). **Closures fuse** their captures inline after the
   fn pointer (`{fn, cap0, cap1, …}`), so creation is a *single* allocation (the fn pointer moves
   into the env object that 8.2 already allocated) and the value is one word instead of two — a
   small win over 8.2 on the hot path. The impl receives the object as its first argument and reads
   captures from fields 1…N. `any I` boxes keep `{witness, payload}` (payload stays a uniform
   pointer, required for type-erased dispatch), costing one extra allocation per box vs. 8.2.
   This diverges from Swift's by-value *thick function* / inline existential container (Swift can
   nest a managed pointer in a by-value aggregate because ARC, not statepoints, scans it); it is the
   representation precise statepoint roots require.

### D2 · GC strategy + late rewrite

`gc "statepoint-example"` on **every function we emit** — free functions, methods, actor handlers,
witness/property thunks, closure impls, spawn routines — since any of them can be a frame on the
stack at a safepoint (a caller needs a stack map at each of its calls). Runtime C declarations stay
plain.

**Pipeline: `mem2reg`/`sroa` before the rewrite, all before codegen.** `RewriteStatepointsForGC`
runs **after** the optimization passes (8.5.3) so opts see ordinary pointers and the statepoint
spill/reload noise is introduced last. For us this ordering is also a **correctness prerequisite,
not only performance (see D6):** our lowering puts every local in an alloca, and the rewrite pass
tracks only GC pointers that are SSA register values — so `mem2reg`/`sroa` must run first to promote
those allocas, or the pass finds almost no roots. 8.4 runs at least `mem2reg`/`sroa` before the
rewrite even before the full `-O` pipeline lands (8.5). Order:
`lower → verify → mem2reg/sroa (→ full opt in 8.5) → rewrite-statepoints-for-gc → codegen → object`.

**`gc-leaf-function` on non-GC runtime calls (perf lever).** The rewrite pass turns *every* call
into a statepoint by default — including runtime C functions that cannot trigger GC, forcing
needless root spill/reload around them. Mark those declarations `"gc-leaf-function"` so the pass
skips them. Provisional classification (re-audit when GC goes live in M6; conservative — when
unsure, leave it non-leaf, since mislabeling a GC-triggering call as leaf is the unsound direction):
- **leaf** (no GC-heap alloc, no fiber yield): `printf`, `rt_str_lit`, `rt_str_concat`,
  `rt_mutex_new`, `rt_mutex_unlock`.
- **non-leaf** (allocates on the GC heap, or parks the fiber so a GC can run): `rt_alloc`,
  `fiber_spawn`, `spawn_join`, `rt_sleep_ms`, `rt_read_line`, `rt_mutex_lock`.
`rt_str_*` are leaf only while `String` is runtime-owned (D1); if M6 makes `String` a GC object they
become non-leaf.

### D3 · Safepoint placement + poll form

Two separate needs ride here — **GC root-scan reachability** and **scheduler fairness** — and
they use different mechanisms (`m8-spec.md` §8.0.4-B). Keeping them straight is what fixes the
elision logic below.

- **Placement — sparse (8.0.7).** GC safepoints at **call sites** (statepoints are the calls
  themselves once rewritten) and at **loop back-edges** that would otherwise be safepoint-free.
  A moving GC can only scan/relocate a fiber at a statepoint, so every loop must *reach* one.
- **Loop-poll placement — the opposite of eliding compute loops.** A loop whose body already
  contains a call or an allocation hits a statepoint every iteration anyway, so its back-edge poll
  is **redundant → elide it there.** A loop with **no call and no allocation** (pure arithmetic)
  reaches *no* statepoint on its own — it is exactly the loop that a moving collector cannot make
  progress against and that would have unbounded time-to-safepoint — so it **must keep a poll.**
  (An earlier draft had this backwards. TTSP is a first-order cost under LXR's frequent short
  pauses, so the compute-loop poll is load-bearing, not optional.) The poll is placed only where a
  loop would otherwise be safepoint-free. **Implemented (8.4.2)** as an IR-level approximation:
  "reaches a safepoint" = the body's *top-level* statements unconditionally perform a **non-leaf**
  call or a heap allocation. Leaf builtins (`print`, `concat`, string literals) and pure value
  construction (`struct`/`enum`) don't count; a safepoint nested inside an `if`/`while`/`switch` arm
  doesn't count (it may not run every iteration), so when unsure a poll is placed — conservative in
  the safe direction. The poll is emitted at the loop **header**, so every back-edge (fall-through
  and `continue`) passes through it each iteration. M6 re-audits against precise codegen safepoints
  when the collector is live.
- **Poll form — deferred to M6 (not decided in 8.4.2).** Two candidates, both still open: (a)
  **protected-page load** — read one byte from a per-carrier poll page normally readable; to request
  a safepoint the runtime `mprotect`s it `PROT_NONE`, the load faults, the handler parks the fiber.
  Near-zero steady state (a single load, no branch), but relies on a `SIGSEGV`/`SIGBUS` handler
  cooperating with `ucontext` fiber stacks. (b) **branch-on-flag** — load a per-carrier flag +
  predicted-not-taken branch. Simpler, no signal handler, but a load *and* a branch every poll. The
  8.4.2 seam is **form-agnostic** — a call to the `__nomu_poll` stub — so the choice does not affect
  the inert phase; M6 settles it (microbenchmark + signal-handler viability) when it arms the poll
  and fills the stub's inline body.
- **Fairness via signals, not polls.** Scheduler preemption of a compute-bound fiber (stop a hog
  so peers on its carrier run) uses **Go-style async preemption** — SIGURG the carrier, park the
  fiber. This is decoupled from GC: a signal stops a fiber at an arbitrary PC where no relocatable
  map exists, so it **cannot** carry root scanning (that stays on statepoints), but it needs no map
  to just park-and-switch. So fairness never depends on the loop poll; the poll exists only for
  GC-scan reachability. (M7 owns the preemption trigger; 8.4 only guarantees the poll for GC.)

### D4 · Stack maps + root scanning

LLVM emits a `__llvm_stackmaps` section keyed by safepoint return address. 8.4.3 ships a
**runtime parser** (stackmap v3: function records + per-safepoint location records) exposing "the
live GC-pointer slots at return address R." The collector (M6) walks roots by, for each frame on
a stack, mapping the frame's return address → its stackmap record → the live slots.

**Fiber-stack integration (the concurrency seam).** Roots live not only on the running carrier's
stack but on every **parked fiber's** stack (`m6-spec.md` §6.1: "carrier frames + globals +
parked fiber stacks"). Each fiber has its own `ucontext` stack; a parked fiber's saved
stack-pointer + the stackmap let the collector walk it the same way. 8.4 ships the parser and the
single-stack walk (smoke test on the running stack); wiring the scan across all parked fibers is
M6, but the parser API is shaped for it (walk takes a stack range + SP, not "the current stack").

### D5 · Inline seams (alloc / write-barrier / poll)

All three emitted **inline-shaped** — fast path inline, slow path an out-of-line stub — and
**inert** now (`m8-spec.md` §8.0.7). Inertness must be provable: 8.2 output unchanged.

- **Alloc fast path.** MMTk bump-pointer shape: load per-carrier `cursor`/`limit`, `new = cursor
  + size`, compare `new <= limit`, branch to slow (`rt_alloc`) or store `cursor = new` and use the
  old cursor. Emitted at every construction that today calls `rt_alloc` (class/actor/env/box).
  **Inert:** the TLAB `limit` is 0, so the fast path always branches to slow = plain `rt_alloc`;
  the inline compare/bump is present but never taken. M6 arms the TLAB.
- **Write barrier.** LXR's dominant mutator cost, so the fast path **must** inline (a call stub
  loses LXR's premise). LXR's is a **coalescing** barrier: on the first mutation of an object per
  epoch it logs the object (records old referents); the common already-logged case just tests a
  **"logged" bit in the object header** and does the store. So the inline fast path is roughly
  *GEP the header → test bit → branch → store*, which means the **object-header layout
  (`m6-spec.md` §6.1) must place that bit where an `addrspace(1)`-interior GEP reaches it in one
  step** — the barrier seam, the `addrspace(1)` model (D1), and the header are co-designed. Emitted
  at every store of an `addrspace(1)` value into an `addrspace(1)` object field (reference-typed
  field writes). **Inert:** the seam body is just the store — no header touch yet — behind an
  inlinable `__nomu_write_barrier(obj, slot, val)` M6 fills. 8.4 leaves the object header as the
  single vestigial `i64` slot it is today; M6 subdivides it (RC / mark / logged bits + type-id).
- **Cancellation / preemption poll.** The same poll as D3, emitted at back-edges (and M7 adds
  explicit cancellation points). **Inert:** the poll page/flag is never armed, so the load never
  faults / the branch never taken. **Implemented (8.4.2)** as the `__nomu_poll` stub below; M6 fills
  its body with the chosen poll form. (The alloc and write-barrier seams are 8.4.4.)

**Seam representation.** Emit each seam as a call to an `alwaysinline __nomu_gc_alloc` /
`__nomu_write_barrier` / `__nomu_poll` with a **trivial body** now (tail-call `rt_alloc` / plain
store / no-op poll), rather than open-coding the full bump-pointer compare/branch or barrier shape
at every site with it disabled. Both are equally inlinable after M6, but the stub keeps the inert
phase clean (far less dead IR to prove inert) and gives M6 a single body to replace instead of N
call sites. The one requirement is that the seam is inlinable, so M6/M7 fill the *body* and the
call sites vanish.

### D6 · GC references in stack memory — SSA-resident default (A), explicit root slot fallback (B)

`RewriteStatepointsForGC` only tracks and relocates GC pointers that are **SSA register values**
at a safepoint (it splices `gc.relocate` into the value's def-use edges). A GC reference sitting in
an alloca that `mem2reg`/`sroa` cannot promote — an address-escaping value aggregate, chiefly a
mutating method passing `self` by pointer, or a large by-value aggregate the ABI spills to memory —
is invisible to the pass. Under a moving collector that pointer goes stale after a relocation.

**Invariant.** At every safepoint, each live GC reference is either **(1)** an SSA register value
the pass tracks, or **(2)** inside a heap object traced by the object map. Keep category **(3)** —
references in escaping stack memory — empty.

- **A (default) — keep it register-resident.** Lower ref-carrying value aggregates so their
  reference fields stay SSA-promotable across safepoints: pass/return small aggregates by value,
  do nested field updates with `insert`/`extractvalue` rather than address-based GEP, and inside a
  by-pointer callee hoist `self`'s reference fields into locals (promotable) rather than reloading
  through the pointer across each safepoint. `mem2reg`/`sroa` then promote them and the rewrite
  pass tracks them. No runtime mechanism; stays on the stack.
- **B (fallback) — root the residual explicitly.** Where A cannot guarantee register-residency
  (a large aggregate the ABI passes indirectly; any remaining address-escape), spill the
  aggregate's GC-reference fields into a small per-frame root slot registered with the runtime; the
  collector scans those slots alongside the statepoint stack maps. Stack-resident, spills only the
  pointer fields, and the cost is proportional to the residual, not to every call — so it stays off
  the shadow-stack throughput path.
- **C rejected.** Boxing ref-carrying aggregates onto the heap loses cache locality (D5 rationale /
  8.0.7); ruled out.

**Why A plus B, rather than A alone.** A cannot promise soundness for large ref-carrying aggregates
passed to non-inlined calls: on arm64 an aggregate over 16 bytes is passed indirectly (a pointer to
a memory copy), and LLVM's handling of GC pointers nested inside first-class aggregate values is a
rough edge. Soundness comes first, so B is the guaranteed backstop for what A cannot prove it
covers. A carries the common, small case at zero overhead; B is the cheap, stack-resident insurance
for the rest.

**Pure value types are untouched.** A struct or enum of primitives (`Point{x,y}`, a matrix) holds
no GC pointers, so it is never a root, never spilled for GC, never relocated — copied and moved
freely. The A/B question only engages an aggregate that mixes values with references and crosses a
non-inlined call.

**Collections (intended design).** Model `Array`/`Dictionary`/`String` after Swift: a value struct
wrapping a single pointer to a heap **class buffer**, with count/capacity/elements in the buffer.
This sits in A's fast path — the struct is one register-wide GC pointer, and the elements are
heap-to-heap references traced by the object map, never stack roots. Mutation via a by-pointer
(`inout`) receiver is the one B-adjacent spot, and it roots a single pointer (often avoidable by
hoisting inside the callee), so collections carry no B performance penalty.

**8.4 vs M6.** The lowering-side work — A's SSA-friendly lowering and B's spill/register placement —
is 8.4; the B slot spills are emitted as inert seams (like D5's alloc/barrier/poll), so the call
sites exist now. Activating the runtime scan of those root slots is M6.

- **8.4.0 — done.** Spike (above). The statepoint → stackmap path links and emits through our C-API

  pointer is live across a safepoint (relocations are no-ops — nothing moves); the emitted object
  carries `__llvm_stackmaps`. Frontend tests pass.
- **8.4.2 — done, green.** Safepoints at calls (implicit post-rewrite) + a back-edge safepoint poll
  on loops that would otherwise be safepoint-free (D3). Elision policy implemented (IR-level
  approximation; see D3). The poll is the inert `__nomu_poll` seam (an `internal alwaysinline
  gc-leaf` no-op stub, D5), emitted at the loop header. Poll **form deferred to M6** (the seam is
  form-agnostic). Exit met: verified the poll is present and reached every iteration on a pure
  compute loop and elided on a loop that already calls/allocates; corpus **byte-identical** to 8.2.
- **8.4.3** — stackmap parser + single-stack root walk (D4). Exit: a smoke test on a known-answer
  program recovers the **exact** live GC-root set at a forced safepoint.
- **8.4.4** — alloc / barrier / poll seams (D5), inline-shaped and provably inert; plus the D6
  root-slot spill seam placed at escaping-aggregate sites (inert — the runtime scan activates in
  M6). Exit: seams present in IR, inline-shaped, corpus output unchanged.

**8.4 exit (from `m8-spec.md`):** every safepoint emits a parseable stack map; the smoke test
recovers the exact live roots on a known-answer program; the three seams are present,
inline-shaped, and provably inert (corpus unchanged vs. 8.2). Hands M6 a working precise-root +
barrier substrate.

## Risks / watch items

- **Statepoint pass links + Mach-O stackmap section** — *resolved (8.4.0)*: links, runs, and emits
  `__llvm_stackmaps` on arm64/Mach-O through the C API. Shim not needed.
- **No GC pointer in a by-value first-class aggregate across a safepoint** — *resolved (8.4.1)*: the
  pass can't relocate one (`support for FCA unimplemented`). `any I`/closures are heap-boxed so their
  value is a scalar `addrspace(1)` pointer; user structs mixing values and references are D6's A/B
  concern. Watch for any new by-value aggregate that bundles a managed pointer (e.g. a future
  multi-word `some`/tuple lowering) — it must not cross a call as an FCA.
- **Statepoint codegen quality** — spill/reload around safepoints, opt inhibition; mitigated by
  late insertion + sparse safepoints + narrow `addrspace(1)` liveness (D1, D3). Keep the boundary
  clean enough to revisit the root mechanism if measured quality is inadequate (8.0.8).
- **Poll-handler ↔ fiber stacks** — the protected-page SIGSEGV handler must cooperate with
  `ucontext` switching; if unclean, fall back to branch-on-flag (D3).
- **Address-space hygiene** — a missed cast or an `addrspace(1)` value reaching a C call
  un-recorded is a latent root bug; one explicit cast site per crossing (D1) keeps it auditable.
