# Backend — LLVM codegen, GC substrate, symbol mangling

**Status:** working draft, as-built. How Nomu lowers to a native binary: backend strategy, the GC backend substrate (statepoints, seams, pass pipeline), symbol mangling, and the generic witness-passing ABI (§4, design — not yet built). Where this sits in the pipeline is in [`architecture.md`](architecture.md); the tier that lowers into it is [`ssair.md`](ssair.md). Status tags: **Decided**, **Deferred**, **Open**.

## 1. Backend strategy

- **Prototype: emit C or bind a simple backend** — throwaway scaffolding to get native execution fast and validate the surface + type system + runtime integration without building production codegen. — **Decided (direction); retired once LLVM landed.**
- **Release builds: LLVM**, for peak native performance, driven via a stable interface. — **Decided; M9 built (2026-08-03).**
- **Debug/dev builds: consider Cranelift** for fast compiles. — **Deferred** (past M9 — a later fast-compile play once LLVM iteration pain bites).
- **MLIR** if heavy language-specific optimization is wanted. — **Not pursued for M9 (2026-07-31)**; plain LLVM. Reconsidered only if heavy custom optimization is later wanted.

**M9 mechanism — Decided; M9 built (2026-08-03).** (M9 is done — 8.1–8.4 and the 8.5.2/8.5.3 perf items; its dedicated build-plan spec was retired once it shipped, as was the M6 GC spec — the GC-substrate facts M6 rests on are folded into the "GC backend substrate" note below.) Drive LLVM via its **C API** (`import LLVM_C`) from Swift (Decided 2026-08-01): importing LLVM's **C++** modules via Swift cxx-interop does not build (`Format.h` `operator<<` ambiguity under interop), whereas the C API builds/links/runs and covers IR + `TargetMachine` + `DIBuilder` + pass pipeline (incl. `rewrite-statepoints-for-gc`). Full C++ reach stays available through a **thin C++ shim** (ordinary C++, no interop) for rare C-API gaps (`DIBuilder` variant parts, custom passes). LLVM is brought in via the **`llvm/llvm-project` Bazel overlay** (`http_archive` at a pinned commit → `@llvm-project//llvm` `cc_library` targets), built from source and hermetic. `swift-llvm-bindings` evaluated and not used. (The earlier "hand-written C++ shim" is the fallback for gaps, not the primary path.) **GC roots via LLVM statepoints** (`addrspace(1)` + `statepoint-example` + RewriteStatepointsForGC → stack maps the MMTk binding reads as precise roots) — chosen as the *most performant* precise-root mechanism for a moving collector (return-address-keyed stack maps, as HotSpot/.NET; the shadow-stack alternative taxes every call and is rejected on performance). The mutator-performance levers are the **inlinable alloc/barrier/poll seams** — the alloc bump-pointer fast path, the write barrier (the dominant cost under LXR's RC), and the safepoint poll are emitted **inline** at the LLVM level, only slow paths as calls; statepoints inserted **late** so opts run first. Scope is **LLVM-only, minimal-correct** — no MLIR, no Cranelift, no incremental in M9.

## 2. GC backend substrate (as built, M6 · 2026-08-12)

The facts the moving GC rests on, folded here when the M6 spec retired (the shipped compiler + runtime are the record):

- **Three inline seams** (`internal alwaysinline`, emitted by `LLVMGenRuntime.swift`), shipped inert in M9 · 8.4 and filled by M6:
  - `__nomu_gc_alloc(i64 size) -> ptr addrspace(1)` at every managed allocation — a statepoint (not `gc-leaf`); M6 filled the per-carrier bump-pointer TLAB fast path (load cursor/limit, bump, branch to `rt_alloc` slow path).
  - `__nomu_write_barrier(obj, slot, val)` — `gc-leaf`, at every managed-reference field write; M6 filled the generational logging barrier (GEP the header from `obj`, test the logged bit, log on first mutation). The header and barrier are co-designed so the logged bit sits where an interior GEP from `obj` reaches it in one step.
  - `__nomu_poll()` — `gc-leaf`, at the header of loops reaching no other safepoint; M6 filled the branch-on-flag form (`runtime.md` §6).
- **`mem2reg`/`sroa` before the statepoint rewrite is a correctness prerequisite**, not just perf: the lowering puts every local in an `alloca`, and `RewriteStatepointsForGC` tracks only SSA-value GC pointers, so promotion must run first or almost no roots are found. Pipeline: `function(mem2reg,sroa),…,rewrite-statepoints-for-gc` (debug) / `default<O2>,rewrite-statepoints-for-gc` (release); the rewrite runs **last** either way. Every emitted function carries `gc "statepoint-example"`. (SSAIR values are already SSA, so for scalars the mem2reg-before-statepoint dependency is gone — `ssair.md`.)
- **`gc-leaf` classification** (callers skip the statepoint): leaf = `printf`, `rt_str_lit`, `rt_mutex_new/unlock`; non-leaf/statepoint = `rt_alloc`, `fiber_spawn`, `spawn_join`, `rt_sleep_ms`, `rt_read_line`, `rt_mutex_lock`, and (once `String` became a GC object) the allocating `rt_str_concat`.
- **Stack-map parser + root walk** ship in `runtime.c`: `nomu_gc_stackmap_init` parses `__llvm_stackmaps` (v3) into a return-address → GC-slot index; `nomu_gc_walk_current` drives a libunwind cursor reporting each live root (SP-relative slots, callee-saved registers recovered per frame). Precise (excludes dead-on-stack objects). A parked fiber's saved `ucontext` is walked the same way (`runtime.md` §6).
- **Object header** is a subdivided `i64` (mark/log bits + type-id; the vestigial `refcount` dropped). Class/actor objects are `{ header, fields… }`; the object model's size/scan tables are in `c-types.md`.

**The gating runtime engineering** the GC integration (via MMTk) introduced: precise stack maps / safepoints (needed because Immix/LXR move objects), the object model (how to scan an object for references), and write-barrier insertion — co-designed with codegen.

**SSAIR tier — GC-precision invariants.** The optimizer tier's transforms must preserve GC precision under the moving collector — address-space / root identity, promotion soundness, barrier obligations, safepoint coverage. The invariants (I1–I10) + the master property + the `Tn` forced-GC test obligations are in [`ssair.md`](ssair.md), enforced by `verifySSAIR` after every pass; they rest on the statepoint / root / barrier machinery above.

**Resolved backend↔GC couplings** (M6 spec retired; the code is the record):

- **Runtime language + MMTk binding.** MMTk is Rust and exposes a C ABI; the irreducible Rust is a `VMBinding` binding crate, while callers can stay C. Resolved at M6 under two invariants that keep every option open: (1) **single allocation seam** — every heap allocation goes through one codegen-controlled call, so the allocator is swappable with a localized change; (2) **explicit, scannable object model** — object shapes carry a clear header and discoverable pointer layout, so a C or Rust binding (and LLVM-emitted barriers/maps) can scan them precisely — no representation tricks that assume conservative-only scanning. Codegen target stays C-free (SSAIR→LLVM); emitting Rust was rejected (`unsafe`-everywhere, throwaway before LLVM).
- **GC precision vs. backend ordering.** Resolved (2026-07-30): the **LLVM backend precedes the moving collector**. A moving collector (Immix) needs precise stack maps the C backend can't emit; the C-path bridges (shadow stack, conservative scanning) degrade the *performance* thesis the moving GC exists to validate. So LLVM statepoints supply precise roots first, then the moving collector rests on them; both shipped in that order (object model + precise scan: `memory-model.md` §3). Parked fiber stacks are scanned precisely via per-fiber saved SP/PC + frame maps (`runtime.md` §6).

## 3. Symbol mangling — Decided (M4.15)

Generated Nomu symbols share C's global namespace, so an unmangled name matching a libc symbol (`abs`, `read`, `free`, `time`, …) is a compile/link collision (surfaced when the prelude's `abs` clashed with libc `abs`). Every **globally-visible generated identifier** is therefore mangled.

**Stale-doc correction (found during modules planning, `plans/tasks/100-modules.md`):** the intended "one module — `src/codegen/sources/Mangle.swift`, the single swap point" no longer exists. There is no `src/codegen/` and no `Mangle.swift`; the logic is **spread** — generic-argument 9-encoding lives in `midend/sources/Monomorphize.swift`, and `nomu_` name construction is scattered across `llvmgen/*` (`LLVMGenCallables`, `SSAIRToLLVM`, `LLVMGen`, …), with "Mangle" surviving only in comments. Task 100.2 (which extends mangling to encode the package + module path) should **consolidate mangling back into a single capability module** (154-style caseless-enum namespace) to restore the swap point.

- **Scheme:** fully-qualified `nomu_<module>_<scope…>_<symbol>` — the module, any enclosing scopes, then the symbol, each **9-encoded** (reversible) and joined by `_`, so the join is unambiguous (a literal `_` becomes `90`, a `.` becomes `91`, the escape `9` becomes `99`). Escape and codes are **all digits** deliberately: letters are never rewritten, so every letter in a mangled name is a real source letter and words stay readable (a digit run is machinery). A top-level symbol has no scope (`abs` → `nomu_main_abs`); a method's scope is its type (`Rect.area` → `nomu_main_Rect_area`). The **module is an implied `main`** until real modules exist (`modules.md`). Plain names stay readable; noise appears only on underscores, dots, and the rare digit-`9`. Fully de-mangleable.
- **Scope:** free functions, nominal types, methods / actor handlers, enum value tags (+ the tag enum type), and synthesized constructor / `release` / `deinit`. **Not** mangled: struct fields and locals/params (scoped in C, so no global collision) and runtime ABI symbols (`rt_*`, `String`, `Closure`, `printf`…). **`main` → `nomu_main`** is the sole exemption — the runtime entry calls it by that fixed name.
- **Why this scheme (priority order: no-collision > readable > de-mangleable > perf):** ruled out the naive `_`-join (ambiguous on underscores/overloads); rejected `$` (a GCC/Clang extension, not ISO C) and `__`/leading-`_` delimiters (**reserved by the C standard** — UB / libc-internal clashes); rejected Itanium-style dense mangling and disambiguator hashes (unreadable, and perf/size is the lowest priority). 9-encoding is portable ISO C, reversible, and clean for the common case; the digit escape (vs. GHC's letter `z`) keeps letters readable as words.
- **Forward (M5+):** the module segment is already in the grammar (real module names replace the implied `main` when modules land); extend `Mangle` to encode **generic type arguments** for monomorphized instances (e.g. `Box<Int>`) and **arg types** if/when overloading is wired into codegen — all additive to the same grammar.
- **Module extensions — Decided (modules design, `../language/modules.md`).** The module segment becomes the real **package + relative module path** (the `pkg` keyword and import aliases resolve to the real package before mangling; the import path never appears). Package **version is not encoded** — the single-version policy means one version per package per build, so it is unneeded for collision-freedom; revisit only if a stable-ABI/binary-distribution story later wants versioned symbols. Visibility maps to linkage: `private`/`internal`/`package` → hidden/internal, `public` → external.
- **Compression — Decided: none, for now.** Back-reference/substitution compression (Itanium `S_`, Rust v0 `B`) is declined to preserve the read-without-a-demangler property (a back-reference is an opaque index). It is **fork-coupled**: external-symbol volume — and thus compression's payoff — scales with separate compilation vs whole-program mono. Revisit if measured symbol size / link time on generic-heavy code justifies it; it stays additive to the grammar. If taken later, prefer **selective** compression (generic-argument and module-prefix tails only), leaving base names plainly readable.
- **ABI stability — Decided: none.** The mangling is an unstable internal contract (the single swap point), free to change between compiler versions. Consequences: artifacts are not cross-version linkable, so packages are consumed as source and recompiled (matches the single-version, repo-wide, source-built model), and the compiled interface artifact is a build-time cache tied to the compiler version, not a stable distribution format. This is the Rust/Go/Zig stance; a stable ABI becomes a distinct future decision only if Nomu ships compiled packages across compiler versions.

## 4. Generic witness-passing ABI — Decided (design, task 100.4.3); not yet built

The calling convention for an **erased** generic — one compiled once and called across a module boundary, the debug witness baseline (`../language/modules.md`; plan in `../plans/tasks/100-modules.md` §100.4.3). Swift's model: **value-witness tables** carry a type's size and value lifecycle; **protocol witness tables** — the existing conformance ABI in `llvmgen/LLVMGenWitness.swift` (slot layout, per-conformance globals, `witnessDispatch`) — carry requirement dispatch, reused unchanged.

- **Value-witness table (VWT).** One per concrete type used as a type argument — an internal const global `vwt_<type>`, built on demand (mirrors the per-conformance witness globals). Fixed layout `{ i32 size, i32 align, i32 type_id, i32 flags, ptr copy, ptr move, ptr destroy }` (the four `i32`s pack into two words, keeping the pointers naturally aligned):
  - `size` / `align` — byte size and alignment; the erased body sizes its `T` buffers from these. `i32` is ample (a by-buffer value never approaches 4 GiB; alignment is a small power of two).
  - `type_id` — the runtime type-id keying the GC trace map, so a scanner reads the buffer's pointer layout. **`i32` to match the object header**, which carries the type-id in its low 32 bits (bit 32 = mark, bit 33 = forwarded; `stdlib/runtime.nomu`). Cross-module type-id stability is task 100.4.7.
  - `flags` — value-witness flags; the first bit is **POD/trivial**, letting the erased body inline a `memcpy` and skip the indirect `copy` / `move` calls and `destroy` entirely for trivial types. Remaining bits reserved.
  - `copy(dst, src)` / `move(dst, src)` / `destroy(val)` — value-semantic init-copy, init-move, and teardown over `ptr`s (a POD type sets the trivial flag and leaves these as `memcpy` / no-op). Function pointers are addrspace 0 (static, like witness tables). Array-of-`T` `stride` is deferred until arrays of a type parameter are exercised.
  - *Revisit (size reduction, deferred — not worth optimizing now):* under the tracing GC (no refcount, `memory-model.md`; value copy shares embedded references with no retain/release, and value types have no deterministic destructor — that is §6's separate resource mechanism), `copy` / `move` are likely `memcpy` and `destroy` a no-op for essentially every type, which would collapse the three function pointers away and shrink the VWT to pure layout metadata (`{ size, align, type_id, flags }`). Confirm no value type needs custom teardown before relying on it.
- **Calling convention.** For an erased `fun f<T: I, U: J & K>(…) -> R`, hidden leading parameters precede the value parameters in this fixed order: (1) one **VWT pointer per type parameter** in declaration order (`T`, `U`); (2) one **PWT pointer per (type parameter, bound)**, type parameters in declaration order, bounds in the interface's sorted order (`T:I`, `U:J`, `U:K`); (3) if the return type mentions a type parameter, a caller-allocated **result-buffer pointer** (sret-style). The normal value parameters (`self` for a method, then declared params) keep their existing positions after these.
- **Indirect values.** A value whose type mentions a residual type parameter (a bare `T`, or a composed `Box<T>`) is passed and returned **indirectly** — a `ptr` to a caller-allocated buffer of `VWT.size` bytes at `VWT.align`. Concrete-typed params keep their by-value ABI. A composed type's VWT is derived from its layout plus the in-scope type-parameter VWTs (**open:** derived-VWT synthesis; the first cut handles a bare `T`, whose VWT is the passed pointer).
- **Requirement dispatch.** A requirement call on a `T`-typed receiver loads the slot from the `(T, I)` PWT (the existing `witnessSlots` index scheme) and calls it with `self` = the value-buffer pointer. **Open reconciliation:** existing thunks take a heap box payload (`addrspace(1)`); the erased path passes a stack buffer (`addrspace(0)`), so the thunk self-ABI must accept a value pointer regardless of provenance.
- **Mangling (§3).** The erased symbol is the generic's qualified name with **no type-argument suffix** (`nomu_<module>_f`); monomorphized specializations keep their `<args>` suffix, so the two never collide — one erased symbol per public generic.
- **Interface artifact.** No new `.nmi` surface: the generic signature + bounds (task 100.4.1) already tell a consumer how many VWTs / PWTs to pass and in what order, and the consumer emits VWTs for its own concrete type arguments from layout it computes locally.
